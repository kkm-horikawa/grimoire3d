# Grimoire3D v0.3.0 plan

On November 20, 2026, the owner approved ordinary quote layouts, the combined markup and list proposals, and the chapter-order design. The goal covered implementation, review, release, and public verification.

## Intended result

Authors can turn existing nested Markdown into books and specify chapter order in YAML. Readers can use ordinary quotes and common syntax on the grimoire's paper. The README and CLI-generated public documentation explain the same behavior. Verification includes checks, actual browser rendering, pull requests, the npm package, GitHub Release, and GitHub Pages.

## Implementation scope

- Add a chapters list to each folder's index.md front matter to order its direct Markdown files and subfolders.
- Append unlisted items in natural filename order, and report missing or duplicate entries.
- Use the approved thin gold rule and inset for ordinary quotes.
- Style task lists, horizontal rules, collapsible notes, math, definitions, highlighted code, and footnotes using the combined proposal.
- Style unordered and ordered lists, including nesting, wrapped lines, two-digit markers, and lists starting above one.
- Check long content, nested content, narrow screens, keyboard interaction, static HTML, and the JavaScript reader.

## README and public guides

Use short examples to explain:

- Each folder directly under docs is a book; its Markdown files are chapters.
- Loose Markdown files directly under docs share another book.
- Nested folders remain within the same book; each index.md introduces its group.
- Title search appears with seven or more books, or whenever a book has a category or publication date.
- Chapter ordering, its default order, and how unlisted items are included.
- A complete index.md YAML example with title, description, socialImage, noindex, cover settings, category, date, and chapters.
- Site-wide URL, locale, and author settings in grimoire.yml, including canonical URLs and sitemap generation.
- Source examples together with rendered syntax and appearance notes.

Keep the README concise and link to the detailed public guides. Verify that the documentation agrees with the released product.
